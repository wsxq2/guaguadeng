# 测试

新实现的测试放在此目录，使用 Python 标准库 `unittest`，无需额外测试依赖。

从项目根目录运行：

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

已安装可编辑包时可省略 `PYTHONPATH=src`。当前包含 45 个测试（含多组子测试）：

- 卡牌与牌组：输入范围、唯一性、不可变性。
- 领牌：拆牌、数量、重复提交、手牌归属、输入不变。
- 跟牌与管牌：配型优先、严格压牌、8 点门槛、最大低牌兜底、无法压牌及混合牌选择。
- 判胜：完整同点数优先、相同点数先出者胜；合法动作枚举覆盖不同花色。
- 引擎：只读快照、阶段与顺序检查、原子失败、下一轮领牌、轮庄、累计积分、结算唯一、中途结束和新场重置。
- 完整对局：20 组固定随机种子，每组连续两局；逐步检查 40 张牌守恒，并核对胜者仅获自己出的牌、获牌总数 10、总积分不变。

- 观察与策略：隐藏手牌交换不改变观察、公开字段与历史、快照不可变、无效 ID、随机可复现、空候选拒绝、输入不变，以及四个策略在 5 组种子下各完成连续两局。

以根目录 [Rules.md](../Rules.md) 为规范，不以旧实现作为正确性标准。
直接使用测试表达规则案例，不另建规则示例文档。

## 工作方式

- 按小步 TDD 推进：先写测试，确认因目标行为未实现而失败，再实现并重构。
- 用参数化案例表达具体手牌、轮内出牌记录、待提交牌和预期结果。
- 同时覆盖合法出牌与应拒绝的出牌，验证失败原因及失败后状态不变。
- 测试公开行为，避免依赖私有方法、内部调用顺序或 GUI。
- 随机发牌和完整对局测试使用可复现的随机源。

实施顺序和模型职责见 [开发说明](../docs/development.md)。

## 文件组织

- `domain/test_card.py`：卡牌与牌组。
- `domain/test_lead.py`：领牌验证（原 `test_rules.py`）。
- `domain/test_follow.py`：跟牌、管牌、合法动作枚举，以及严格比较的关联案例。
- `domain/test_scoring.py`：判胜与计分。
- `domain/test_state.py`：轮内状态派生属性。
- `domain/test_observation.py`：公开观察信息和隐藏手牌隔离。
- `domain/helpers.py`：共享的测试卡牌与轮记录构造函数。
- `strategies/test_random_strategy.py`：随机策略选择行为。
- `engine/test_game.py`：引擎生命周期与状态一致性。
- `engine/test_strategy_game.py`：多个策略与引擎协作的完整对局。

按行为主题拆分，不要求测试文件与源码文件一一对应。

## 可选 UI 测试

`ui/test_preview.py` 检查选牌规则桥接及 QML 在横竖屏尺寸下加载。需要安装 `.[ui]`；无 PySide6 时跳过 UI 测试，不影响核心测试。测试使用 offscreen 和软件渲染，不代替 Android 真机触摸与视觉验收。

- `tools/test_build_android.py`：代理首次设置、已有配置保留与备份、拒绝含凭据 URL、构建版本固定及重复执行一致性。

- `ui/test_controller.py`：真人非法出牌、公开视图、提示、定时 AI 完整对局、结算续局，以及结束后取消 AI。

- `ui/test_table.py`：正式 QML 牌桌加载、安全区域、按钮交互完整对局、续局、结束确认及重开。
